# xkeen-sub

CLI-утилита для управления подписками XKeen на Keenetic (Entware).

**Статус проекта: в разработке.** Проект находится на ранней стадии, функциональность ещё не завершена и не прошла полноценное тестирование. На данный момент это **нерабочая в практическом смысле утилита**: её нельзя считать готовым инструментом и использовать на рабочем роутере.

**Скачать:** [страница релизов xkeen-sub на GitHub](https://github.com/PaulMarkey1/xkeen-sub/releases). Когда будут опубликованы готовые сборки, они появятся на этой странице.

## Установка на роутер

Инструкции ниже приведены для будущих тестовых сборок. Пока проект не готов к эксплуатации, устанавливать его на рабочий роутер не рекомендуется.

Для установки потребуется работающий Entware и доступ к интернету. Установщик определяет архитектуру Entware, скачивает подходящий бинарник из последнего GitHub Release, проверяет его запуск и версию, показывает, какая версия устанавливается, и устанавливает её в `/opt/sbin/xkeen-sub`.

Поддерживаемые архитектуры — те же, что у XKeen jameszero:
- ARM64 / `aarch64`
- MIPS little-endian / `mipsel`
- MIPS big-endian / `mips`

После публикации релиза выполнить на роутере по SSH:

```sh
opkg update
sh -c "$(curl -fsSL https://raw.githubusercontent.com/PaulMarkey1/xkeen-sub/main/install.sh)"
```

После установки запуск:
```sh
xkeen-sub
xkeen-sub setup
```

GitHub Actions собирает бинарники для трёх архитектур и прикладывает их к релизу при push тега вида `v*`. Первый релиз создаётся через GitHub → Releases → Draft a new release, например с тегом `v0.0.2`. После завершения workflow установщик сможет скачивать его assets.

## Текущее состояние

Создан Rust-проект. Реализованы CLI-каркас, меню настройки, добавление, просмотр, удаление и редактирование подписок. Удаление пересчитывает ID и префиксы после удаления. Команда `update` согласована, но ещё не реализована. Команда `status` отложена до финального этапа. Реализованы обновление самой программы (`uxs`), выбор версии для переустановки (`reinstall`) и удаление (`uninstall`).

## Запуск и команды

- `xkeen-sub` — вывести справку с номером установленной версии. Запуск без аргументов не открывает меню.
- `xkeen-sub help` — показать справку.
- `xkeen-sub --version` или `xkeen-sub -V` — вывести номер версии.

- `setup` — настройка подписок:
  - `add` — добавить подписку.
  - `list` — просмотреть подписки.
  - `del` — удалить подписку.
  - `edit` — редактировать название или ссылку подписки.
  - `help` — справка по настройке.

- `uxs` — обновить программу до последнего GitHub Release.
- `reinstall` — выбрать и переустановить одну из последних пяти версий GitHub Releases для архитектуры роутера.
- `uninstall` — удалить программу и файлы настроек.
- `update` — обновить все подписки; `xkeen-sub update subN` — обновить только указанную подписку (логика согласована, функция ещё не реализована).

Вложенные команды указываются после родительской команды: например, `xkeen-sub setup add`.

## Обновление программы

Команда `xkeen-sub uxs` показывает текущую версию, определяет ABI по `opkg print-architecture`, включая суффиксы версий Entware (например, `mipsel-3.4_kn`), скачивает соответствующий бинарный файл последнего GitHub Release, показывает версию загруженного файла, проверяет его запуск и только после успешной проверки заменяет текущий исполняемый файл. `uname -m` используется лишь как ограниченный резервный вариант; если он сообщает неоднозначный `mips`, обновление прекращается, чтобы не установить бинарник другой endian-архитектуры. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

Команда `xkeen-sub reinstall` показывает текущую версию, получает пять последних опубликованных релизов GitHub, оставляет версии, для которых доступен бинарник архитектуры роутера, и предлагает выбрать одну из них. После выбора показывает выбранную версию, скачивает бинарник во временный файл и проверяет его запуск. Если бинарник поддерживает вывод версии, программа также сверяет её с выбранным тегом. Старые релизы, в которых ещё нет команды `--version`, остаются доступными для переустановки. Только после проверок программа атомарно заменяет текущий исполняемый файл. Если загрузка или проверка не пройдёт, установленная версия останется на месте. Постоянная резервная копия не создаётся. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

## Удаление программы

Команда `xkeen-sub uninstall` спрашивает, нужно ли удалить `sub.json`, затем запрашивает подтверждение удаления. Исполняемый файл и `config.json` удаляются; `sub.json` удаляется только при согласии пользователя. При отмене подтверждения файлы не изменяются.

## Меню настройки

При запуске `xkeen-sub setup` показывается меню. Пользователь выбирает пункт вводом цифры:

```text
XKEEN-SUB — НАСТРОЙКА
────────────────────────
1. Добавить подписку
2. Просмотреть подписки
3. Удалить подписку
4. Редактировать подписку
0. Выход
```

Пункт 4 (`edit`) открывает меню редактирования подписки.

## Функция list — просмотр подписок

Команда `xkeen-sub setup list` выводит каждую подписку отдельным блоком. Верхняя и нижняя границы блока и вертикальная черта в начале каждой строки окрашены в жёлтый цвет. Названия полей (`ID:`, `Имя:`, `Префикс:`, `Ссылка:`) окрашены в голубой вместе с двоеточием. Значения остаются системного цвета терминала. Ссылка выводится на отдельной строке. Если имя не задано, отображается `—`. Между блоками — пустая строка. Если список пуст, выводится сообщение «Список подписок пуст.» .

## Функция add — добавление подписки

### Последовательность действий

1. Спросить: «Добавить название подписки?»
   - `1 Да` — перейти к вводу названия.
   - `2 Нет` — пропустить название (значение `null`).
   - `0 Вернуться` — вернуться без добавления подписки.
2. При выборе «Да» запросить: «Введите название для подписки:».
3. Запросить: «Введите URL подписки:».
4. Выполнить синтаксическую валидацию URL.
5. При успешной проверке сохранить запись в `sub.json`.

### Проверка URL

- Для валидации используется Rust crate `url`.
- Разрешены только схемы HTTP и HTTPS.
- URL должен содержать host.
- Проверка синтаксическая: при добавлении не выполняется сетевой запрос, содержимое подписки не скачивается, доступность сервера не проверяется.
- При некорректном URL программа повторно запрашивает адрес.

### Хранение данных

Файл списка подписок: `/opt/etc/xkeen-sub/sub.json`.

Файл общих настроек `/opt/etc/xkeen-sub/config.json` зарезервирован для настроек приложения; список подписок хранится отдельно в `sub.json`.

Структура данных:

```json
{
  "subscriptions": [
    {
      "id": "sub1",
      "name": "Germany",
      "url": "https://example.com/sub1",
      "prefix": "sub1--Germany--"
    },
    {
      "id": "sub2",
      "name": null,
      "url": "https://example.com/sub2",
      "prefix": "sub2--"
    }
  ]
}
```

Начальный шаблон `etc/xkeen-sub/sub.json` содержит пустой массив подписок. Шаблон общих настроек `etc/xkeen-sub/config.json` пока пустой JSON-объект.

Поля записи:
- `id` — идентификатор формата `subN`, где `N` — порядковый номер подписки.
- `name` — название или `null`, если пользователь отказался от названия.
- `url` — введённый URL подписки.
- `prefix` — строка префикса, сформированная на основе `id` и названия.

### Формирование id и prefix

- Если название задано: `subN--<name>--`. Пример: `sub1--Germany--`.
- Если название отсутствует: `subN--`. Пример: `sub2--`.
- Нумерация начинается с 1 и ведётся последовательно.
- После удаления подписки записи перенумеровываются подряд; их `id` и `prefix` пересчитываются. Пропусков в нумерации не должно быть.

## Функция edit — редактирование подписки

Команда `xkeen-sub setup edit` доступна как пункт 4 меню настройки.

### Выбор подписки

1. Программа выводит список существующих подписок для выбора.
2. Пользователь выбирает подписку по номеру.
3. В меню выбора подписки есть пункт «Вернуться» — его номер следует следующим по порядку после списка подписок.
4. Пункт `0. Выход` завершает команду `edit` и возвращает пользователя в консоль.

### Действия с выбранной подпиской

После выбора подписки программа показывает меню:

1. Изменить название.
2. Изменить ссылку.
3. Вернуться.
0. Выход.

- «Вернуться» возвращает к списку подписок для выбора.
- `0. Выход` завершает команду `edit` и возвращает пользователя в консоль.
- При изменении названия пустой ввод удаляет название (сохраняет `null`), а префикс пересчитывается.
- Новый URL проверяется так же, как при добавлении: разрешены только HTTP и HTTPS, адрес должен содержать host; сетевой запрос не выполняется.
- После успешного изменения названия или ссылки программа сохраняет изменения в `sub.json` и возвращается в меню действий с той же выбранной подпиской.

## Функция update — обновление подписок (согласовано, ещё не реализовано)

Команды:
- `xkeen-sub update` — обновить все подписки.
- `xkeen-sub update subN` — обновить только подписку с указанным ID.

### Общий порядок работы

1. Подписки обрабатываются последовательно.
2. После обработки каждой подписки сразу выводится её результат и подробный отчёт. Общий отчёт в конце вместо по-подписочного вывода не используется.
3. Ошибка одной подписки не останавливает обработку остальных.
4. Если хотя бы одна подписка успешно загружена и обработана, её изменения могут быть применены независимо от ошибок других подписок.
5. Если ни одна подписка не ответила, конфигурации не изменяются. В этом случае выполняется отдельная проверка интернет-соединения.
6. Если интернет-соединение отсутствует, выводится сообщение: «Отсутствует интернет-соединение». Также указывается, что конфигурация XKeen не изменена.
7. Если интернет доступен, но ни одна подписка не ответила, сообщается об ошибках доступа к серверам подписок; конфигурация не изменяется.

### Файлы загруженных подписок

- Каждая подписка скачивается в отдельный файл; общий файл для загрузки всех подписок не используется.
- Имя файла формируется из поля `prefix` соответствующей подписки с добавлением расширения `.json`.
- Если название подписки задано, имя файла имеет вид `subN--ИМЯ.json`, например `sub1--Germany.json`.
- Если название отсутствует, имя файла имеет вид `subN--.json`, например `sub2--.json`.
- Файл каждой подписки обрабатывается независимо от файлов остальных подписок.

### Получение и проверка данных

- URL каждой подписки берётся из `sub.json`.
- Содержимое подписки загружается по HTTP или HTTPS.
- Для сетевых запросов предусматривается тайм-аут.
- Проверяются результат HTTP-запроса, наличие содержимого и корректность полученных данных.
- Некорректная или недоступная подписка пропускается; её прежняя конфигурация сохраняется.
- Ошибка одной подписки не мешает обновлению остальных.
- Если все подписки не ответили, наличие интернета проверяется отдельно. Для проверки следует использовать несколько внешних HTTPS-адресов, чтобы недоступность одного проверочного узла не приводила к ложному выводу об отсутствии интернета.

### Сравнение подключений

В подписках сравниваются только подключения и их параметры. Правила маршрутизации в состав подписки не входят.

Идентификатор подключения при сравнении — его `Tag`.

- Tag есть в новой подписке, но не было в предыдущей — подключение добавлено.
- Tag был в предыдущей подписке, но отсутствует в новой — подключение удалено.
- Tag присутствует в обеих версиях, но параметры отличаются — подключение изменено. В этом случае старое подключение заменяется целиком новым объектом со всеми актуальными параметрами; изменение не считается удалением и добавлением.
- Если Tag изменился, связь между старым и новым подключением не устанавливается: старое считается удалённым, новое — добавленным.
- Неизменённые подключения учитываются количественно, без перечисления каждого из них.

### Повторяющиеся Tag внутри одной подписки

Если несколько подключений в одной подписке имеют одинаковый Tag:

- Подключения с одинаковым Tag сравниваются между собой по всем параметрам.
- Полностью идентичные подключения считаются дубликатами: сохраняется одно, остальные удаляются.
- Если подключения с одинаковым Tag отличаются параметрами, им назначаются уникальные Tag с последовательными суффиксами: исходный Tag, `Tag--1`, `Tag--2`, `Tag--3` и так далее.
- Нумерация суффиксов начинается с `--1` и увеличивается для каждого следующего отличающегося подключения с тем же исходным Tag.

### Отчёт по каждой подписке

Отчёт выводится сразу после обработки соответствующей подписки, по мере выполнения команды. Он должен подробно показывать:

- Добавленные подключения — перечислить их Tag.
- Удалённые подключения — перечислить их Tag.
- Изменённые подключения — указать Tag и перечислить только изменившиеся параметры. Для каждого параметра показать старое и новое значение под отдельным заголовком подключения.
- Неизменённые подключения — показать только их количество.
- Если изменений нет — вывести сообщение «Изменений нет. Подписка актуальна».
- Если подписка не отвечает или произошла другая ошибка — вывести понятную причину и указать, что прежняя конфигурация этой подписки сохранена.

Пример структуры отчёта:

```text
Подписка: Germany

Добавлены:
  + Germany-1
  + Poland

Удалены:
  - France

Изменены:
  Germany-2
    Изменённые параметры:
      server:
        Было: old.example.com
        Стало: new.example.com
      port:
        Было: 443
        Стало: 8443

Без изменений: 5
```

### Оформление терминального вывода

Для команды `update` используется единый цветовой стиль проекта. Цвет применяется к смысловым элементам, а не к целым длинным блокам текста:

- Заголовки отчётов и этапов обработки — жёлтым.
- Название подписки выделяется в заголовке её отчёта.
- Успешное завершение обновления — зелёным.
- Ошибки — красным; предупреждения — жёлтым.
- Добавленные подключения и их Tag — зелёным.
- Удалённые подключения и их Tag — красным.
- Названия изменённых параметров — голубым.
- Подписи «Было» и «Стало», а также старые и новые значения — обычным цветом терминала.
- Количество подключений без изменений — обычным цветом.
- Нейтральный текст и пояснения — обычным цветом.

Для каждой подписки сначала показывается ход обработки, затем сразу её итоговый отчёт. Этапы индикатора процесса: загрузка подписки, проверка данных, сравнение подключений и подготовка изменений. У каждого этапа отображается понятный результат: например, `OK` или причина ошибки. Индикатор относится только к текущей подписке и не заменяет подробный отчёт.

При ошибке отчёт явно сообщает, что прежняя конфигурация этой подписки сохранена. Если обновление завершилось без изменений, выводится: «Изменений нет. Подписка актуальна».

Пример оформления (обозначения цветов в квадратных скобках — пояснения, а не буквальный текст терминала):

```text
[ЖЁЛТЫЙ] Обновление подписки: Germany
Загрузка подписки...          OK
Проверка данных...            OK
Сравнение подключений...      OK
Подготовка изменений...       OK

[ЗЕЛЁНЫЙ] Подписка Germany обработана

[ЗЕЛЁНЫЙ] Добавлены:
  + Germany-1
  + Poland

[КРАСНЫЙ] Удалены:
  - France

[ЖЁЛТЫЙ] Изменены:
  Germany-2
    [ГОЛУБОЙ] server:
      Было: old.example.com
      Стало: new.example.com
    [ГОЛУБОЙ] port:
      Было: 443
      Стало: 8443

Без изменений: 5
```

### Применение изменений

Перед записью новых данных необходимо подготовить результаты обработки подписок. Применение должно предусматривать резервное копирование изменяемых конфигураций и возможность восстановления предыдущего состояния при ошибке записи. Детальный алгоритм подготовки, резервного копирования, атомарной замены и отката будет отдельно согласован до реализации.

## Границы текущего этапа

Пока не реализованы:
- команда `status`;
- реализация команды `update`, скачивание и разбор содержимого подписок;
- изменение конфигураций XKeen / управление Xray;
- Web UI.

Справка должна обновляться при добавлении каждой функции и точно отражать реально реализованные возможности.
