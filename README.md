# xkeen-sub

CLI-утилита для управления подписками XKeen на Keenetic (Entware).

**Статус проекта: в разработке.** Проект находится на ранней стадии, функциональность ещё не завершена и не прошла полноценное тестирование. На данный момент это **нерабочая в практическом смысле утилита**: её нельзя считать готовым инструментом и использовать на рабочем роутере.

**Скачать:** [страница релизов xkeen-sub на GitHub](https://github.com/PaulMarkey1/xkeen-sub/releases). Когда будут опубликованы готовые сборки, они появятся на этой странице.

## Установка на роутер

Инструкции ниже приведены для будущих тестовых сборок. Пока проект не готов к эксплуатации, устанавливать его на рабочий роутер не рекомендуется.

Для установки потребуется работающий Entware и доступ к интернету. Установщик определяет архитектуру Entware, скачивает подходящий бинарник из последнего GitHub Release и устанавливает его в `/opt/sbin/xkeen-sub`.

Поддерживаемые архитектуры — те же, что у XKeen jameszero:
- ARM64 / `aarch64`
- MIPS little-endian / `mipsel`
- MIPS big-endian / `mips`

После публикации релиза выполнить на роутере по SSH:

```sh
opkg update
sh -c "$(curl -fsSL https://raw.githubusercontent.com/PaulMarkey1/xkeen-sub/main/install.sh)"
```

После установки запуск:
```sh
xkeen-sub
xkeen-sub setup
```

GitHub Actions собирает бинарники для трёх архитектур и прикладывает их к релизу при push тега вида `v*`. Первый релиз создаётся через GitHub → Releases → Draft a new release, например с тегом `v0.0.2`. После завершения workflow установщик сможет скачивать его assets.

## Текущее состояние

Создан Rust-проект. Реализованы CLI-каркас, меню настройки, добавление, просмотр и удаление подписок. Удаление пересчитывает ID и префиксы после удаления. Команда `status` пока не реализуется. Реализованы обновление программы (`uxs`), выбор версии для переустановки (`reinstall`) и удаление (`uninstall`).

## Запуск и команды

- `xkeen-sub` — вывести справку. Запуск без аргументов не открывает меню.
- `xkeen-sub help` — справка.
- `xkeen-sub setup` — открыть меню настройки.
- `xkeen-sub setup help` — справка по настройке.
- `xkeen-sub setup add` — добавить подписку.
- `xkeen-sub setup list` — просмотр подписок.
- `xkeen-sub setup del` — удалить подписку.
- `xkeen-sub uxs` — обновить программу до последнего GitHub Release.
- `xkeen-sub reinstall` — выбрать и переустановить одну из последних пяти версий GitHub Releases для архитектуры роутера.
- `xkeen-sub uninstall` — удалить программу и файлы настроек.

## Обновление программы

Команда `xkeen-sub uxs` определяет ABI по `opkg print-architecture`, включая суффиксы версий Entware (например, `mipsel-3.4_kn`), скачивает соответствующий бинарный файл последнего GitHub Release, проверяет его запуск и только после успешной проверки заменяет текущий исполняемый файл. `uname -m` используется лишь как ограниченный резервный вариант; если он сообщает неоднозначный `mips`, обновление прекращается, чтобы не установить бинарник другой endian-архитектуры. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

Команда `xkeen-sub reinstall` получает пять последних опубликованных релизов GitHub, оставляет версии, для которых доступен бинарник архитектуры роутера, и предлагает выбрать одну из них. После выбора программа скачивает бинарник во временный файл, проверяет его запуск и только затем атомарно заменяет текущий исполняемый файл. Если загрузка или проверка не пройдёт, установленная версия останется на месте. Постоянная резервная копия не создаётся. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

## Удаление программы

Команда `xkeen-sub uninstall` спрашивает, нужно ли удалить `sub.json`, затем запрашивает подтверждение удаления. Исполняемый файл и `config.json` удаляются; `sub.json` удаляется только при согласии пользователя. При отмене подтверждения файлы не изменяются.

## Меню настройки

При запуске `xkeen-sub setup` показывается меню. Пользователь выбирает пункт вводом цифры:

```text
XKEEN-SUB — НАСТРОЙКА
────────────────────────
1. Добавить подписку
2. Просмотреть подписки
3. Удалить подписку
0. Выход
```

## Функция list — просмотр подписок

Команда `xkeen-sub setup list` выводит каждую подписку отдельным блоком. Верхняя и нижняя границы блока и вертикальная черта в начале каждой строки окрашены в зелёный цвет. Названия полей (`ID:`, `Имя:`, `Префикс:`, `Ссылка:`) окрашены в голубой вместе с двоеточием. Значения остаются системного цвета терминала. Ссылка выводится на отдельной строке. Если имя не задано, отображается `—`. Между блоками — пустая строка. Если список пуст, выводится сообщение «Список подписок пуст.».

## Функция add — добавление подписки

### Последовательность действий

1. Спросить: «Добавить название подписки?»
   - `1 Да` — перейти к вводу названия.
   - `2 Нет` — пропустить название (значение `null`).
   - `0 Вернуться` — вернуться без добавления подписки.
2. При выборе «Да» запросить: «Введите название для подписки:».
3. Запросить: «Введите URL подписки:».
4. Выполнить синтаксическую валидацию URL.
5. При успешной проверке сохранить запись в `sub.json`.

### Проверка URL

- Для валидации используется Rust crate `url`.
- Разрешены только схемы HTTP и HTTPS.
- URL должен содержать host.
- Проверка синтаксическая: при добавлении не выполняется сетевой запрос, содержимое подписки не скачивается, доступность сервера не проверяется.
- При некорректном URL программа повторно запрашивает адрес.

### Хранение данных

Файл списка подписок: `/opt/etc/xkeen-sub/sub.json`.

Файл общих настроек `/opt/etc/xkeen-sub/config.json` зарезервирован для настроек приложения; список подписок хранится отдельно в `sub.json`.

Структура данных:

```json
{
  "subscriptions": [
    {
      "id": "sub1",
      "name": "Germany",
      "url": "https://example.com/sub1",
      "prefix": "sub1--Germany--"
    },
    {
      "id": "sub2",
      "name": null,
      "url": "https://example.com/sub2",
      "prefix": "sub2--"
    }
  ]
}
```

Начальный шаблон `etc/xkeen-sub/sub.json` содержит пустой массив подписок. Шаблон общих настроек `etc/xkeen-sub/config.json` пока пустой JSON-объект.

Поля записи:
- `id` — идентификатор формата `subN`, где `N` — порядковый номер подписки.
- `name` — название или `null`, если пользователь отказался от названия.
- `url` — введённый URL подписки.
- `prefix` — строка префикса, сформированная на основе `id` и названия.

### Формирование id и prefix

- Если название задано: `subN--<name>--`. Пример: `sub1--Germany--`.
- Если название отсутствует: `subN--`. Пример: `sub2--`.
- Нумерация начинается с 1 и ведётся последовательно.
- После удаления подписки записи перенумеровываются подряд; их `id` и `prefix` пересчитываются. Пропусков в нумерации не должно быть.

## Границы текущего этапа

Пока не реализованы:
- команда `status`;
- скачивание и разбор содержимого подписок;
- изменение конфигураций XKeen / управление Xray;
- Web UI.

Справка должна обновляться при добавлении каждой функции и точно отражать реально реализованные возможности.
