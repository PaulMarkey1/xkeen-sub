# xkeen-sub

CLI-утилита для управления подписками XKeen на Keenetic (Entware).

**Статус проекта: в разработке.** Проект находится на ранней стадии, функциональность ещё не завершена и не прошла полноценное тестирование. На данный момент это **нерабочая в практическом смысле утилита**: её нельзя считать готовым инструментом и использовать на рабочем роутере.

**Скачать:** [страница релизов xkeen-sub на GitHub](https://github.com/PaulMarkey1/xkeen-sub/releases). Когда будут опубликованы готовые сборки, они появятся на этой странице.

## Установка на роутер

Инструкции ниже приведены для будущих тестовых сборок. Пока проект не готов к эксплуатации, устанавливать его на рабочий роутер не рекомендуется.

Для установки потребуется работающий Entware и доступ к интернету. Установщик определяет архитектуру Entware, скачивает подходящий бинарник из последнего GitHub Release, проверяет его запуск и версию, показывает, какая версия устанавливается, и устанавливает её в `/opt/sbin/xkeen-sub`.

Поддерживаемые архитектуры — те же, что у XKeen jameszero:
- ARM64 / `aarch64`
- MIPS little-endian / `mipsel`
- MIPS big-endian / `mips`

После публикации релиза выполнить на роутере по SSH:

```sh
opkg update
sh -c "$(curl -fsSL https://raw.githubusercontent.com/PaulMarkey1/xkeen-sub/main/install.sh)"
```

После установки запуск:
```sh
xkeen-sub
xkeen-sub setup
```

GitHub Actions собирает бинарники для трёх архитектур и прикладывает их к релизу при push тега вида `v*`. Первый релиз создаётся через GitHub → Releases → Draft a new release, например с тегом `v0.0.2`. После завершения workflow установщик сможет скачивать его assets.

## Текущее состояние

Создан Rust-проект. Реализованы CLI-каркас, меню настройки, добавление, просмотр, удаление и редактирование подписок. Удаление пересчитывает ID и префиксы после удаления. Реализован контрольный запуск `update`: он загружает и сравнивает подписки, формирует группы Обновлённого и Итогового Outbound, готовит изменения балансировщиков и Observatory, проверяет конфигурацию Xray и выводит полный предварительный план. Команда доступна как `xkeen-sub update` и `xkeen-sub update subN`. Контрольный запуск не применяет изменения и не записывает конфигурации, архив или baseline. Проверка Xray выполняется на временных копиях файлов в системном временном каталоге; действующий каталог конфигурации используется только для чтения. Реализация конвертации произвольных форматов подписок и этап применения пока не завершены. Команда `status` отложена до финального этапа. Реализованы обновление самой программы (`uxs`), выбор версии для переустановки (`reinstall`) и удаление (`uninstall`).

## Запуск и команды

- `xkeen-sub` — вывести справку с номером установленной версии. Запуск без аргументов не открывает меню.
- `xkeen-sub help` — показать справку.
- `xkeen-sub --version` или `xkeen-sub -V` — вывести номер версии.

- `setup` — настройка подписок:
  - `add` — добавить подписку.
  - `list` — просмотреть подписки.
  - `del` — удалить подписку.
  - `edit` — редактировать название или ссылку подписки.
  - `help` — справка по настройке.

- `uxs` — обновить программу до последнего GitHub Release.
- `reinstall` — выбрать и переустановить одну из последних пяти версий GitHub Releases для архитектуры роутера.
- `uninstall` — удалить программу и файлы настроек.
- `validation` — показать текущий режим проверки; `validation on|off|alert` — изменить его.
- `update` — выполнить контрольный запуск обновления всех подписок без применения изменений; `xkeen-sub update subN` — проверить только указанную подписку.

Вложенные команды указываются после родительской команды: например, `xkeen-sub setup add`.

## Обновление программы

Команда `xkeen-sub uxs` показывает текущую версию, определяет ABI по `opkg print-architecture`, включая суффиксы версий Entware (например, `mipsel-3.4_kn`), скачивает соответствующий бинарный файл последнего GitHub Release, показывает версию загруженного файла, проверяет его запуск и только после успешной проверки заменяет текущий исполняемый файл. `uname -m` используется лишь как ограниченный резервный вариант; если он сообщает неоднозначный `mips`, обновление прекращается, чтобы не установить бинарник другой endian-архитектуры. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

Команда `xkeen-sub reinstall` показывает текущую версию, получает пять последних опубликованных релизов GitHub, оставляет версии, для которых доступен бинарник архитектуры роутера, и предлагает выбрать одну из них. После выбора показывает выбранную версию, скачивает бинарник во временный файл и проверяет его запуск. Если бинарник поддерживает вывод версии, программа также сверяет её с выбранным тегом. Старые релизы, в которых ещё нет команды `--version`, остаются доступными для переустановки. Только после проверок программа атомарно заменяет текущий исполняемый файл. Если загрузка или проверка не пройдёт, установленная версия останется на месте. Постоянная резервная копия не создаётся. Файлы `sub.json` и `config.json` не изменяются. Для загрузки требуется `curl` или `wget`.

## Удаление программы

Команда `xkeen-sub uninstall` спрашивает, нужно ли удалить `sub.json`, затем запрашивает подтверждение удаления. Исполняемый файл и `config.json` удаляются; `sub.json` удаляется только при согласии пользователя. При отмене подтверждения файлы не изменяются.

## Меню настройки

При запуске `xkeen-sub setup` показывается меню. Пользователь выбирает пункт вводом цифры:

```text
XKEEN-SUB — НАСТРОЙКА
────────────────────────
1. Добавить подписку
2. Просмотреть подписки
3. Удалить подписку
4. Редактировать подписку
0. Выход
```

Пункт 4 (`edit`) открывает меню редактирования подписки.

## Функция list — просмотр подписок

Команда `xkeen-sub setup list` выводит каждую подписку отдельным блоком. Верхняя и нижняя границы блока и вертикальная черта в начале каждой строки окрашены в жёлтый цвет. Названия полей (`ID:`, `Имя:`, `Префикс:`, `Ссылка:`) окрашены в голубой вместе с двоеточием. Значения остаются системного цвета терминала. Ссылка выводится на отдельной строке. Если имя не задано, отображается `—`. Между блоками — пустая строка. Если список пуст, выводится сообщение «Список подписок пуст.» .

## Функция add — добавление подписки

### Последовательность действий

1. Спросить: «Добавить название подписки?»
   - `1 Да` — перейти к вводу названия.
   - `2 Нет` — пропустить название (значение `null`).
   - `0 Вернуться` — вернуться без добавления подписки.
2. При выборе «Да» запросить: «Введите название для подписки:».
3. Запросить: «Введите URL подписки:».
4. Выполнить синтаксическую валидацию URL.
5. При успешной проверке сохранить запись в `sub.json`.

### Проверка URL

- Для валидации используется Rust crate `url`.
- Разрешены только схемы HTTP и HTTPS.
- URL должен содержать host.
- Проверка синтаксическая: при добавлении не выполняется сетевой запрос, содержимое подписки не скачивается, доступность сервера не проверяется.
- При некорректном URL программа повторно запрашивает адрес.

### Хранение данных

Файл списка подписок: `/opt/etc/xkeen-sub/sub.json`.

Файл общих настроек `/opt/etc/xkeen-sub/config.json` зарезервирован для настроек приложения; список подписок хранится отдельно в `sub.json`.

Структура данных:

```json
{
  "subscriptions": [
    {
      "id": "sub1",
      "name": "Germany",
      "url": "https://example.com/sub1",
      "prefix": "sub1--Germany--"
    },
    {
      "id": "sub2",
      "name": null,
      "url": "https://example.com/sub2",
      "prefix": "sub2--"
    }
  ]
}
```

Начальный шаблон `etc/xkeen-sub/sub.json` содержит пустой массив подписок. Шаблон общих настроек `etc/xkeen-sub/config.json` содержит режим проверки `validation: alert`.

Поля записи:
- `id` — идентификатор формата `subN`, где `N` — порядковый номер подписки.
- `name` — название или `null`, если пользователь отказался от названия.
- `url` — введённый URL подписки.
- `prefix` — строка префикса, сформированная на основе `id` и названия.

### Формирование id и prefix

- Если название задано: `subN--<name>--`. Пример: `sub1--Germany--`.
- Если название отсутствует: `subN--`. Пример: `sub2--`.
- Нумерация начинается с 1 и ведётся последовательно.
- После удаления подписки записи перенумеровываются подряд; их `id` и `prefix` пересчитываются. Пропусков в нумерации не должно быть.

## Функция edit — редактирование подписки

Команда `xkeen-sub setup edit` доступна как пункт 4 меню настройки.

### Выбор подписки

1. Программа выводит список существующих подписок для выбора.
2. Пользователь выбирает подписку по номеру.
3. В меню выбора подписки есть пункт «Вернуться» — его номер следует следующим по порядку после списка подписок.
4. Пункт `0. Выход` завершает команду `edit` и возвращает пользователя в консоль.

### Действия с выбранной подпиской

После выбора подписки программа показывает меню:

1. Изменить название.
2. Изменить ссылку.
3. Вернуться.
0. Выход.

- «Вернуться» возвращает к списку подписок для выбора.
- `0. Выход` завершает команду `edit` и возвращает пользователя в консоль.
- При изменении названия пустой ввод удаляет название (сохраняет `null`), а префикс пересчитывается.
- Новый URL проверяется так же, как при добавлении: разрешены только HTTP и HTTPS, адрес должен содержать host; сетевой запрос не выполняется.
- После успешного изменения названия или ссылки программа сохраняет изменения в `sub.json` и возвращается в меню действий с той же выбранной подпиской.

## Функция update — контрольный запуск

Команды:
- xkeen-sub update — контрольный запуск всех подписок.
- xkeen-sub update subN — контрольный запуск одной подписки.

Команда пока работает только в режиме предварительного просмотра. Она скачивает и сравнивает подписки, формирует Обновлённый и Итоговый Outbound, рассчитывает изменения пользовательских подключений и архива, готовит routing и Observatory, выполняет доступные проверки и выводит подготовленные JSON-документы.

**Рабочие конфигурации, архив и baseline не изменяются.** Применение конфигурации, запись baseline и архива, резервное копирование и откат будут реализованы отдельно.

### Что делает контрольный запуск

1. Читает sub.json и действующие конфигурации Xray.
2. Загружает выбранные подписки последовательно по возрастанию subN.
3. Сравнивает каждую подписку с её baseline.
4. Если изменений нет, сохраняет соответствующую рабочую группу без повторной загрузки в Итоговый Outbound.
5. Если изменения есть, передаёт в Обновлённый Outbound всю подписку целиком.
6. Сохраняет в плане старые группы подписок, которые не выбраны, не изменились или завершились ошибкой.
7. Обрабатывает пользовательские подключения по совпадению исходного Tag и параметров без учёта Tag.
8. Формирует Итоговый Outbound: подписочные группы по возрастанию номера, затем пользовательские подключения.
9. Подготавливает балансировщики по трём согласованным сценариям и синхронизирует subjectSelector Observatory.
10. Проверяет подготовленную конфигурацию и выводит подробный отчёт.

Если одна подписка завершается ошибкой, остальные продолжают обрабатываться. Если ни одна подписка не прошла обработку, дальнейшая подготовка прекращается.

### Форматы подписок

Текущий загрузчик возвращает исходные байты ответа. Текущий этап сравнения ожидает JSON-документ Xray с массивом outbounds. Конвертация Base64, URI-ссылок и других форматов подписок в Xray JSON ещё не реализована. Такие форматы не следует считать поддерживаемыми.

### Baseline и архив

Baseline каждой подписки находится в /opt/etc/xkeen-sub/ и именуется по её prefix:
- с названием: subN--ИМЯ.json;
- без названия: subN--.json.

Baseline содержит оригинальный документ подписки. В контрольном запуске он только читается; новый файл не записывается.

Архив пользовательских подключений находится по пути /opt/etc/xkeen-sub/old-user-outbound.json. В контрольном запуске существующий архив читается, а новые записи только рассчитываются в памяти.

### Балансировщики

Для балансировщика программы используется Tag xkeen-sub-balancer.

- Если балансировщиков нет, создаётся новый, а подходящие routing.rules[].outboundTag перенаправляются на balancerTag. Outbound с протоколами freedom, blackhole, dns и loopback, а также Tag из api.tag не перенаправляются. Неизвестный outboundTag также заменяется.
- Если балансировщик один, его selector обновляется, если он содержит все Tag Рабочего Outbound. Дополнительные Tag допустимы. Если не содержит — добавляется отдельный xkeen-sub-balancer.
- Если балансировщиков несколько, существующие не меняются; добавляется xkeen-sub-balancer.
- Если xkeen-sub-balancer уже существует, обновляется его selector.
- Selector балансировщика программы заполняется Tag Итогового Outbound.
- Новое уведомление о создании балансировщика будет выводиться только после будущего успешного применения.

Стратегия нового балансировщика — leastPing, в написании Xray.

### Проверка Xray

В режимах validation on и alert контрольный запуск проверяет подготовленный набор конфигураций командой xray run -test -format=json. Для этого создаются временные копии файлов в системном временном каталоге. Действующий каталог /opt/etc/xray/configs используется только для чтения, временные копии удаляются после проверки.

- on — ошибка проверки запрещает будущее применение.
- alert — ошибка выводится как предупреждение.
- off — проверка Xray не запускается.

Проверка не гарантирует доступность удалённых серверов. Автоматический цикл исключения проблемных Outbound по диагностике Xray пока не реализован.

### Что пока не реализовано

- Конвертация не-JSON форматов подписок.
- Автоматическое исключение проблемных Outbound по диагностике Xray.
- Применение подготовленных конфигураций.
- Запись baseline и архива.
- Резервное копирование и откат.
- Команда status.

## Режим проверки подключений — validation

Команды:
- xkeen-sub validation — показать текущий режим.
- xkeen-sub validation on — включить строгий режим.
- xkeen-sub validation alert — включить режим предупреждений.
- xkeen-sub validation off — отключить проверку Xray.

Если параметр validation отсутствует в config.json, используется режим alert.

Режимы управляют проверкой подготовленной конфигурации Xray в контрольном запуске. Они не изменяют файлы конфигурации и не запускают рабочий сервер Xray.


### Принцип проверки параметров

Xray является источником истины для проверки совместимости Outbound. xkeen-sub не должен самостоятельно вводить ограничения, которых нет в Xray: например, проверять UUID собственным регулярным выражением или удалять неизвестные дополнительные поля. Если Xray принимает конфигурацию при xray run -test, программа не должна отклонять её собственной проверкой параметров.

### Результаты экспериментальной проверки Xray 26.10.31

На роутере с Xray 26.10.31 отдельно проверялись VMess и VLESS:
- VMess с обычным UUID — Configuration OK.
- VMess со значением UUID NOT-A-VALID-UUID — Configuration OK.
- VLESS с обычным UUID — Configuration OK.
- VLESS со значением UUID NOT-A-VALID-UUID — Configuration OK.

Результат относится только к этим тестам и не означает, что Xray принимает любые некорректные значения UUID или параметры всех протоколов.
